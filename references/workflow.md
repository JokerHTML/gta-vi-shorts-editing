# End-to-end workflow (full step detail)

Part of the GTA VI Shorts Editing Skill v1.2.0. SKILL.md carries the compact checklist; this file carries the full step text. Load when executing a step.


**Step 0. Topic research, fact ledger, banned list.** Research across **at least 3 independent sources** (at least one official: Rockstar Newswire, Rockstar's official download pages, or the official Rockstar Games YouTube channel). Write a fact ledger (F1–Fn: CONFIRMED / REPORTED / REACTION / CONFIRMED AS UNANNOUNCED / REPORTED - DISPUTED, with a verification note naming the sources read) and a BANNED list (disputed names, unannounced counts/lengths, false "announced" claims, comparisons stated as fact, the word "leak" and any leak handle, product links, wrong relative dates). Schemas in `references/appendix-templates.md`; the complete worked V1 ledger (12 rows) and banned list (10 rows) are in `examples/v1-macca-friends.md`. Dedup against the run's topic log (`TOPIC-LOG.md`: one row per topic with date and air date). For trailer-motion claims, survey at 1fps and claim spans in `trailer-windows.md`; no two videos use the same span; M23-blocked spans are never usable. On a multi-video run the coordinator publishes `RUN-ALLOCATION.md`: a frame belongs to exactly ONE video as hero-or-beat; a hero BACKUP is contingency only, never also a beat in the same video. Within one video, reusing the same still twice with a different crop window is allowed only with a different window AND a named reason in the shot plan (V2 did this: hero + second window); reusing the same window twice is a double-assignment defect.

**Step 1. ChatGPT brief, script, SEO, thumbnail brief.** Paste the brief verbatim into a NEW ChatGPT conversation (`references/chatgpt-brief.md`: verbatim V1 brief, then a fill-in template). Fixed brief elements: 30-59 seconds, English only; official Rockstar material only; no fake claims; numbers as WORDS, never digits, in every number in the script; no product links; vary attribution, never open three VO lines with the same attribution word; no phrase repeated verbatim across beats. Beats are prescribed (hook, what, plot, scale, caveat, countdown — after launch, use the post-launch sixth beat in `references/post-launch.md`). ChatGPT writes every script; no agent-drafted script ships without a ChatGPT rewrite pass. The same return gives the SEO package: title (verbatim, character count stated), description (hook first, facts in order, Sources line, countdown line last, no product links), 12 tags in verbatim brief order, a `CATEGORY` line (Gaming for news Shorts unless the brief's reasoning says Entertainment — the trio's own Studio category was never recorded, so this is the stated default, not a claimed fact), and a thumbnail brief (cover text verbatim, base frame plus backup frame, 1080x1920 9:16, headline in a clean upper portion, safe margins, verify full-res before delivery). SEO PACKS may be written pre-publish; SEO is APPLIED in Studio only after the video is public, unless the owner orders otherwise. **Hook shortlist:** write 5–12 candidate hooks, score each 0–10 on the hook rubric, wait for the human pick before rendering. Hook score (PROVISIONAL, uncalibrated): 2 points each for subject in the first 5 words; a surprise or contrast; ledger-true with no qualifier needed; speakable in under 4 seconds (measured: the hook line's Kokoro stem at speed 1.1 under 4.0s; proxy ≤10 words); no attribution word opening the line. 10 is ship-ready; 8–9 tighten one element; below 8 rewrite via ChatGPT. Hook shapes: correction, result, problem + proof, teaser — and title → first frame → first line must promise the same thing. **First frame = thumbnail:** focal object plus hook text present at frame 1 (M16).

**Step 2. Honesty check (before build).** Hand-recount the script (both counts 90-105); every fact traces to the ledger; banned list clean; attribution varied (M18, M26); countdown exact; dates verified; title character count verbatim; description Sources line present (canonical format: `Sources: Outlet (Date); Outlet (Date); …` — every entry dated; undated only for a source with no publication date, reason noted); 12 tags in order; no product link; thumbnail brief cover text verbatim with base/backup frames and the M27 note. `scripts/validate-build.py` performs the word count, the stem-aware banned grep, and the pool arithmetic; title/tag-count/description/M30/M26/M34 checks remain manual — its output names exactly which checks it ran.

**Step 3. M20 pool gate (BEFORE any VO).** Estimate needed frames (word count × measured pace, plus gaps and holds), triage the pool, count ONLY full-res-verified clean frames (head, middle, tail, AND fade boundaries at full resolution; a contact-sheet tile verdict never counts a span clean). Record in `POOL-GATE-RECORD.md`. If pool < need + slack, STOP before VO, cards, and mix. Keep a running pool ledger across a multi-video run. Measure each source's active picture bounds first (M29): Trailer 2 active y=216..1943; Launch Trailer active y=120..2039. Full-slice safety sampling (M19); check triage against the shared blocklist (M23). Pace: V1 2.94, V2 2.50, V3 2.66 words/sec; planning pace is the slowest, 2.5 words/sec. Need = ceil(spoken words / 2.5 × 30) + gap frames + 2f tail pad. Slack = ceil(10% of need).

**Step 4. VO synthesis (Kokoro).** Venv `$HOME/workspace/.venvs/v1fix1` (kokoro-onnx 0.6.1). Voice `am_adam`, speed 1.1 locked, -40 dBFS trim, 24 kHz, one stem per script sentence. Outputs: `work/vo/s01..sNN.wav` (PCM_16) plus `work/vo_report.json`. Word bypass: if Kokoro mangles a word, bypass it in the SPOKEN text only; on-screen text keeps the correct spelling ("Kaseya" → spoken "Kuh-say-uh", after testing 7 spellings). Always check the voiceover. Channel voice defaults persist in `references/voice.md`.

**Step 5. VO check: exact subtitles via faster-whisper.** Words and spelling come from the SCRIPT (exact); timing comes from Whisper word timestamps. Run faster-whisper **`small`** with `word_timestamps=True` and write `vo_check.json` plus `word_timings.json`. Whisper-over-music artefacts are expected on the final mix: lines mangled over the bed but heard correctly on the clean concat are artefacts, not missing VO. If Whisper hears a word differently, prove it with a fresh Kokoro control synthesis before changing the caption. **Tie-break:** when `small`, `base`, and `tiny` disagree, the fresh Kokoro control synthesis decides.

**Step 6. VO concat (varied gaps, M3).** Concatenate stems with varied gaps (V1: 8/10/6/12/9/8/10/7; V3: 8/5/8/5/8/5; V2's 8 uniform 0.35s gaps were a retired deviation). Output `work/vo_concat.wav` (24 kHz mono) plus `work/timeline.json`. **Pause discipline:** cut dead air over ~0.5s; gaps 0.15–0.25s between sentences; a deliberate 0.5–1s beat only before a reveal, after the hook, or before the CTA — never at 0:00, never true digital silence (a bed must be audible, M4).

**Step 7. Cut stills and motion (active-area windows only, M29, M21).** Still recipe: precrop a 1215x2160 window, then a static 1080x1920 lossless clip; the Remotion Shot component supplies the eased push-in/pull-back (per-segment `motion`: `push` / `pull` / `none` — `none` is the default for motion spans unless the storyboard says otherwise; V2 used alternating push-in/pull-back by segment index), so bake no zoompan. Motion recipe: 9:16 window from the MEASURED active picture only, centre windows, exact frame counts, libx264 crf 0, 30fps, 1080x1920. Default still window: centre x=1312 unless a named exception applies. Frame-count-verify all clips with ffprobe. Shot discipline: ~1 shot per sentence, ≥3s per shot as the aspiration, slow background movement (M24); cuts on every information beat (M22); still windows in the trio were 33–99f; the v3 recipe caps static holds at 2.0s. **Visual velocity:** ≥1 visual event (cut, card change, caption pop, motion change) every 2–3 seconds; first cut at or before 1.5s; roughly half the edit's events in the hook (first ~10s). Material sources: Rockstar Newswire, Rockstar's official download pages, official Rockstar Games YouTube channel only. **This skill builds Shorts from official Rockstar trailers and stills, not from the buyer's gameplay** — GTA VI launches Nov 19, 2026, so no buyer has GTA VI gameplay yet; there is no console-capture section (a capture addendum ships post-launch).

**Step 8. Fact-card strip and captions.** One fact-card strip per video: 3 lines plus a source chip plus a caveat chip, no digits on cards (numbers as words), every line tracing to ledger rows. Each card is a distinct designed component with its own layout, palette, and focal element; two cards sharing a layout, palette, and focal treatment inside one video fail storyboard (template placeholders use three distinct accents: amber statement, coral figure, teal countdown). M34 qualifier on the card at headline size. Read every card on its frame (M28). **Karaoke captions (word-by-word):** 2–4 words visible at a time, fixed lower-third, spring pop-in, keyword colour only on key words — the biggest presentational gap in the trio, now the standard. Remotion `Captions.tsx` is the canonical route; the `.ass` presets in `pro-pack/subtitle-presets/` are the fallback for non-Remotion renders only — never use both on one video. If the ASS fallback is used, burn in during the grade pass, AFTER the LUT and BEFORE the clamp, and upload the matching `.srt` to Studio as the caption track (do not rely on auto-captions alone). No captions during card windows; no caption overlaps a card window; no caption over card text; no lone "the", "a", or "no" on screen. Caption words are script words only, timed from STT. "Footage: Rockstar Games" credit on the opening shot. Canonical caption size: 96px Anton, bottom 168 (v3 style); 88px Anton plus gradient rail, bottom 150 (V2 A/B style) is the alternate, only when the backdrop behind the caption zone is busy or bright. Never mix presets inside one video. Safe-zone margins: 130px sides, 150px top, 200px bottom (M27). **Loop design:** the ending re-hooks the opening (a loop or callback line at ~⅔ pointing back to the hook) so a rewatch feels complete — check the retention graph for the end-rise that proves it.

**Step 9. Mix (VO plus bed, M4, M35).** VO stems at timeline starts; bed ducked to 0.33 under VO, 1.0 in gaps, 0.1s fades; peak-normalize to -1.5 dBFS; output `work/mix.wav` (24 kHz). **Mix ladder (peaks):** VO loudest ~−6 dBFS, music −18 dB, SFX −12 dB, ambience −24/−30 dB; master −14 LUFS, true peak ≤ −1 dBTP; sidechain-duck the bed under VO. Bed: royalty-free, tiled to length if shorter. The trio's own bed is Joker Gaming's original composition and is NOT shipped: use the pad recipe in `references/sourcing-guide.md` (fully specified: C–G–Am–F sine pads, 4s per chord, root-position voicing at C4, 0.3s attack / 0.8s release, loop at the bar line, −27 dBFS RMS) or a named royalty-free track from the YouTube Audio Library, Pixabay Music, or Free Music Archive. If the track requires attribution, it goes on the LAST description line, after the countdown line — the one allowed addition to the description format. Record the bed choice with licence and source URL in the build report. Trailer audio is never used. No commercial music (M35): check audio RIGHTS, not just levels, at assembly and at upload. Stereo warning: the mix is mono; Remotion renders stereo (+~3 dB), so loudnorm passes must account for it. **Music ladder (safest first):** YouTube Audio Library → Pixabay / Free Music Archive royalty-free → Shorts audio library (only inside the Shorts editor, never as a downloaded file) → never a commercial song. Staying ≤59s is a taught risk control: a Short over 60s with a Content ID claim is blocked globally.

**Step 10. Remotion render.** Render in the Pro Pack template (`pro-pack/remotion-template/`); `src/data.ts` is the only file you normally touch. Free-skill users without the Pro Pack use their own Remotion 4 project with the same compositions. Render at **crf 12** (the high-quality master — lossy, not lossless; CRF 0 is rejected by Remotion 4): `npx remotion render src/index.ts JokerTemplate out/raw.mp4 --crf=12 --timeout=120000 --concurrency=2 --pixel-format=yuv420p`. One render at a time on a small machine. The Remotion render outputs full-range video even with `--pixel-format=yuv420p`; that is why Step 11 exists. **Preview-first:** before the full render, render the first 10 seconds at full quality plus a `remotion still` of every card frame, and check them. Before rendering, write and validate the pre-render plan (`references/pre-render-plan.md`). Nothing renders until the plan validates.

**Step 11. Grade, colour-tag fix, loudnorm — ONE canonical order.** **Fix, then grade, one loudnorm pass.** (1) Fix: `./post-render-fix.sh out/raw.mp4 out/fixed.mp4` — the script first measures the raw render's luma range with `signalstats` and applies `pc→tv` conversion ONLY when the values actually span full-range (Y min < 16 or Y max > 235); if the pixels are already limited-range it applies `setparams` tags only. It verifies the output's levels (Y min/max) as well as its tags. Loudnorm runs here, once: single-pass I=-15.5, TP=-2.0, LRA=11. (Nov 16 verification: the raw render measured already TV-range with only the transfer wrong (sRGB) — the old "Remotion always outputs full-range" premise is version-dependent, which is why the gate exists.) (2) Grade: the `grade-pipeline.md` command (deband, grain, LUT, clamp, setparams, crf 18, preset slow) on `out/fixed.mp4` — its input is the fixed file, never the raw render; it contains no range conversion and no loudnorm. (3) Re-measure loudness on the delivered file. **"Two-pass" disambiguation:** loudnorm's built-in dual-pass mode is ONE application of loudnorm; running loudnorm a second time on an already-normalised file is forbidden — with one exception, the documented V3 fix: when the delivered file measures out of band, do ONE audio-only retarget in loudnorm dual-pass (linear) mode with measured inputs (V3's exact values are in `examples/v3-burger-shot.md`), then re-measure. (4) Verify by ffprobe: yuv420p, tv, bt709 ×4, before red-team.

**Step 12. Builder QC on the delivered file (M25: re-measure, never trust).** Duration ≤59s, 1080x1920, 30fps; loudness in band; silencedetect 0 hits; cropdetect 1080:1920:0:0 on EVERY motion span (M21); STT matches the script; frame inspection of card frames, motion head/mid/tail, caption timing; M28 read of every card on its frame; thumbnail viewed full-size at 1080x1920 (builder, red-team, coordinator — three views, M27). Every measurement must trace to the artifact file it cites. **Originality check (YouTube Oct 1, 2026 rule):** every Short must pass "what did I add?" — captions + crop + music alone FAIL. Name the added value in the build report. No graphic violence in the thumbnail or the first 7 seconds.

**Step 13. Red-team gate (independent reviewer, did not build).** Red-team re-runs silencedetect, loudnorm, STT, and frame checks from the delivered file as a matter of course (M25). Named gates, in order: **source-deck → timestamp → layout → technical → human/vision**. A video is not cleared until an independent re-measure from the DELIVERED file confirms the numbers. Rubric below.

**Step 14. Scheduling and upload.** M30 re-derivation at scheduling (see the gates table). M31 check: time-of-day plus eligibility, not just dates. Upload checklist: title keyword-first, ≤100 chars, honest; description complete (hook first, facts in order, Sources line, countdown line last, plus attribution line only if a track requires it); tags 10–14 targeted tags from title/description keywords (never 0, never 2 near-duplicates); category from the SEO pack's CATEGORY line (default Gaming); video language English (never left on "Select"); altered-content AI disclosure YES, always; audience Not made for kids; HD rule: upload as Unlisted, wait for HD 100%, then publish or schedule. After publish/schedule, re-open Studio Details and READ BACK all 8 fields (title, description, tags, category, language, AI disclosure, visibility + schedule time, audience); fix anything wrong immediately and re-verify. Upload the caption file to Studio (or confirm the auto-caption track exists; if missing, recheck in 48h). Record the video ID plus publish time in the upload log. **CTA policy:** every Short ends with one short CTA line in the final beat ("Follow for the next GTA VI update" or the topic's own next step) — prescribed, because the trio shipped without one and had no growth loop. Joker uploads carry no product links and no playlist.

**Step 15. Post-publish results log + iteration (PROVISIONAL).** Record one row per video (video ID, publish time, views, likes, comments, collection date) from the public YouTube page or Studio at a stated date. An uncollected field is "not reported", never zero. Do not use the log to claim the method works: three videos are not a sample. **Iteration rule:** read the retention graph at 48h — early cliff = hook problem, slow slide = pacing, stair-step drop = one bad second, rise at the end = rewatch (loop worked). Change ONE variable on the next upload; keep a 10-Short baseline before judging a change; never delete-and-reupload a flop. Full loop in `references/analytics-iteration.md`. **Thumbnail test:** test two thumbnails (A/B) by default on launch-week videos.
